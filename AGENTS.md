# Agent Rules for Prusa-Firmware

## Agent Directive
Do not execute firmware builds, `./utils/bootstrap.py`, or `./PF-build.sh` unless explicitly asked by the user. Provide information only.

## Project Scope
This fork is intentionally locked to **Original Prusa i3 MK3S** only. Other variants are unsupported by design.

## Architecture
- Firmware code lives in `Firmware/`. Entrypoint is `Firmware/Firmware.ino`.
- Variants are configuration headers in `Firmware/variants/*.h`. CMake auto-discovers them and generates `build_gen/<variant>/CMakeLists.txt` at configure time. **Never edit `build_gen/` manually.**
- `Configuration_prusa.h` is not used in CMake builds; the variant header is injected at compile time.
- C11 / C++17. AVR target disables RTTI, exceptions, and threadsafe statics.

## Build System (reference only)
- `./utils/bootstrap.py` downloads pinned dependencies (avr-gcc 7.3.0, cmake 3.22.5, ninja 1.12.1, prusa3dboards 1.0.6).
- `PF-build.sh` and Arduino IDE builds are deprecated / community-maintained. Prefer CMake if build info is needed.

## Testing
- Host-only Catch2 tests in `tests/`. CMake target `test_run_all`. No cross-compilation needed.

## Style & Patterns
- Match the style of the file being edited. Do not bulk-reformat.
- 4-space indent. Line width ~100. LF, final newline, trim trailing whitespace.
- Header guards: `#ifndef FILENAME_H` / `#define FILENAME_H` (older style) or `#pragma once` (newer). Keep consistency within the file.
- Braces: file-dependent (Allman vs K&R). Mirror the surrounding code.
- Naming:
  - Macros / constants: `SCREAMING_SNAKE_CASE` (`ADC_CHAN_MSK`, `LANG_SIZE_RESERVED`).
  - C functions / globals: `snake_case` (`manage_heater`, `target_temperature`).
  - C++ classes: `PascalCase` (`MMU2`, `Timer`). Methods: `camelCase` (`start`, `expired`, `enabled`).
  - Member variables: `m_camelCase` (`m_isRunning`, `m_started`).
  - Enums: `PascalCase` for type and values (`ResetForm`, `Software`).
  - Structs: `PascalCase` (`Sheet`, `Version`).
- Flash strings: wrap with `PSTR(...)` and use `serialprintPGM` / `serialprintlnPGM`. Flash variables marked `PROGMEM`.
- AVR constraints: no exceptions, no RTTI. Prefer fixed-width types (`uint8_t`, `int16_t`) in hardware-facing code.

## Pattern Rule
Before implementing new logic, inspect 2–3 existing implementations in the same subsystem (same file or directly related headers). Match their error-handling style, state-machine approach, memory management, and naming. Do not bulk-search unrelated directories.

For menu system patterns, read `.opencode/patterns/menu-system.md` before editing.

## Languages / i18n
- PO-based translations in `lang/po/`. `.pot` template is auto-generated by `lang/update-pot.py`. Do not hand-edit `.pot`.
- `LANG_MODE=1` enables multi-language. UI string changes may need PO file updates.

## CI Context
- CI runs on branches `MK3`, `MK3_*` and tags `v*`, `t*`, `c*`.
- `pr-size.yml` tracks binary size for `MK3S_MULTILANG` / `MK3_MULTILANG`.

## Tools
- `tools/` contains host-side Python utilities (EEPROM dump, crash parsing, thermal model decoding). Not part of the firmware build.
